## Issues

### 🔴 HIGH — bot projectiles can't actually hurt you (offline) / credit the host (online)
**File:** `experiences/little-planet/src/modes/match-mode.js` → `_onProjectileHit` (bot-owned branch, ~line 1070).

The new bot shot funnels through `this._request({ type: 'hit', target, damage })` **without the `fromBotId`** that the old `c.onHit` callback used to pass. Fallout:
- **Offline solo / 2p-vs-bots:** `_request` → `sim.request('local', evt)`, so the hit resolves with `shooter = local player`. `match.js` assigns teams by join order (local player = blue), so a red bot's shot on you becomes a **same-team** pair and `_hit()` bails on `target.team === shooter.team`. **Result: bot projectiles deal ZERO damage to the human in solo play.** Bot-vs-bot downs instead bump the human's `kills`.
- **Online (host):** `_request` → `net.event(evt)` not `net.botEvent(item.owner, evt)`, so the server credits the kill to the host and validates against the wrong author.

**Fix (one line):** in the `ownerIsBot` case pass `item.owner`:
```js
this._request({ type: 'hit', target: target.id, damage: item.damage }, item.owner);
```
This restores `sim.request(item.owner, …)` (offline) and `net.botEvent(item.owner, …)` (online), unblocking bot damage and correct scoring.

### 🟠 MEDIUM — possible networked double-application of bot hits
`ownerIsBot` is true on **every** client, so if bot projectiles are replicated to clients (not host-only), each client independently calls `_request` for the same hit. Needs a real 2+ client playtest to confirm whether bot projectiles are host-authoritative only. Suggest gating bot-projectile damage to host-only (treat like remote-human shots on clients).

### ⚪ LOW — dead `onHit` in bot context
The bot context still defines `onHit: (b, target, damage) => …` but `botShoot` no longer calls it. Harmless; delete for clarity.
